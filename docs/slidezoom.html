A patch of another subtype is implanted into a held-out slide; chance is 50%. Zoom finds the patch but the answer doesn't use it: at 0.5–1% the zoom prior doubles the attention on the patch, yet accuracy doesn't move. With an easy cross-organ patch, reading every tile beats random sampling at 0.1%; the zoom adds nothing measurable on top.

How it works

  1. The slide is cut into 128 µm tiles; a frozen encoder turns each into 768 numbers (shared with SlideTalk).
  2. Tiles are grouped into 1 mm sub-regions and 4 mm regions: three memories of the slide.
  3. GPT-2 reads the question. Its four cross-attention layers look at regions, then sub-regions, then tiles, and each layer's attention steers the next.
  4. GPT-2 writes the answer. Only the projection and cross-attention layers are trained (~10M parameters, about 12 minutes on a MacBook).

End to end

The slide is turned into three memories once per question. The first cross-attention reads regions, the second sub-regions, the last two read tiles, so magnification follows GPT-2's depth. The purple arrows are the zoom prior: what each word attended to in one block biases where it looks in the next.

Why β starts at 0

Like the gate g, the zoom strength β is one learned number per layer that starts at 0. At the start the model is an ordinary multi-scale Flamingo model (baseline B2), so any zooming it does is learned because it lowers the loss. Plotting β over training shows whether the model chooses to zoom; in the first runs it stayed below 0.25.

The learned zoom prior has no effect here: with β set to 0 no answer changes, and B2 matches SlideZoom on every slide. No paired difference is significant. Pruning to 8% of the tiles works, but the hierarchy does it, not β. These questions can be answered from almost any part of the slide; a focal-evidence task is next.

Where the zoom prior works

The usual Flamingo block (queries from words, keys and values from the slide, gated residual) plus one new term: the previous block's attention over coarse cells, averaged over heads, is copied to each fine cell's children and added to the scores as β · log a. It is computed per text token, so different questions can zoom to different places.

Findings so far

  1. The zoom makes the model look at small evidence (1.6–2× more attention on a 0.5–1% patch).
  2. But it doesn't improve the answers (same accuracy as the identical model with the zoom off).
  3. Reading every tile beats 512 random tiles on tiny evidence (0.72–0.77 vs 0.66 at a 0.1% patch).
  4. On whole-slide questions, every model scores the same.
  5. The models can't recognise lung subtypes in a patch (chance even at 20% of the slide).
  6. Picking the top regions by their average loses small evidence.
  7. The zoom has to start switched on (started at 0, it never turns on for an easy patch).
